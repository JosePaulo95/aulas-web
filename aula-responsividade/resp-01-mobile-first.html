O que é

O mesmo site em qualquer tela

Celular≈ 360 px de largura

Tela estreita, dedo no lugar do mouse.

Tablet≈ 768 px de largura

No meio do caminho.

Computador1280 px ou mais

Muito espaço pros lados.

Responsivo = o mesmo HTML se adapta à largura da tela. Nada de fazer um site pro celular e outro pro computador.

Falar

  • Responsivo não é “site pequeno”. É um site que muda de jeito conforme o espaço que tem.
  • Os números são só uma referência: o que importa é a largura, em pixels.
  • Prometer: “Vocês vão aprender 4 coisas: a linha mágica, as unidades, mobile-first e media query.”

Tempo

  • 1:30 → 3:00

Com ↓ (só você)

  • Passos: width: 600px (a tela diminui: a caixa não cabe, aparece barra de rolagem) → ↓ width: 100% (cabe, mas no computador fica enorme) → ↓ max-width: 600px (cabe e para de crescer).
  • Depois de cada ↓ a tela faz a animação sozinha. Dá pra arrastar a barra “Tela” pra testar.

Falar

  • px é fixo: 600px é 600px, mesmo que a tela tenha 320. Ela não cabe.
  • 100% = “ocupa tudo que o pai deixar”. Resolve o celular, mas estica demais no computador.
  • max-width = “pode crescer até aqui, mas não passa”. Esse par (width: 100% + max-width) a gente usa o tempo todo.

Erro comum

  • Achar que max-width e width são a mesma coisa. Um é o desejo, o outro é o limite.

Tempo

  • 3:00 → 4:30

Com ↓ (só você)

  • Começa sem a linha: o celular da esquerda mostra a página de computador, espremida. ↓ digita a linha viewport e o celular da direita mostra o site do jeito certo.

Falar

  • Sem essa linha, o celular finge que é um computador de 980px e encolhe tudo pra caber. Resultado: letrinha minúscula.
  • Com ela: “use a largura real da tela”. Aí o CSS responsivo passa a valer.
  • É uma linha só, no <head>, em todo site. Pode copiar e colar sem medo.

Erro comum

  • Esquecer a linha e achar que o CSS não funciona no celular. No computador (F12) parece certo, no celular de verdade não.

Unidades

Medir em px ou em algo que se adapta

pxwidth: 300px;

Fixo. Sempre 300, em qualquer tela.

%width: 50%;

Metade do pai.

remfont-size: 2rem;

Vezes o tamanho da letra da página (16px). 2rem = 32px.

vw / vhwidth: 50vw;

% da tela. 50vw = metade da largura da tela.

Falar

  • Quatro unidades, uma ideia: fixo (px) ou relativo (todas as outras).
  • Relativo a quê? % = ao pai. rem = à letra da página. vw/vh = à tela (v de viewport).
  • vh é igual ao vw, só que pela altura da tela.
  • Não existe a melhor: cada uma serve pra uma coisa. Vamos ver as quatro na prática.

Tempo

  • 6:00 → 7:30

Com ↓ (só você)

  • Passos: 300px → ↓ 50% → ↓ 50vw → ↓ 20rem → ↓ html { font-size: 24px } (só a barra do rem cresce).
  • A caixa tracejada é o pai: tem 80% da tela. Por isso 50% e 50vw são diferentes.

Falar

  • Reparem na animação: a barra de px não se mexe e vaza pra fora.
  • % acompanha o pai. vw acompanha a tela inteira (ignora o pai).
  • rem parece fixo, mas é múltiplo da letra da página. Mudou o html, mudou tudo que usa rem.

Pausa e pratica

  • “Pausem: qual barra vai ficar maior se o pai for 100% da tela? E qual não muda?” (%, vw igual; px e rem não mudam)

Tempo

  • 7:30 → 9:30

Com ↓ (só você)

  • Passos: 24px → ↓ 1.5rem (igual, parece o mesmo) → ↓ 4vw (encolhe com a tela) → ↓ clamp(...) (encolhe, mas tem limites).

Falar

  • px e rem ficam iguais: 1.5 × 16 = 24. A diferença é que rem respeita quem aumentou a letra do navegador (acessibilidade).
  • 4vw: no celular a letra fica minúscula, no monitor gigante, enorme. Sozinho é perigoso.
  • clamp(mínimo, ideal, máximo) = “use o ideal, mas nunca menos que o mínimo nem mais que o máximo”.

Dica do video

  • Pra iniciante: rem pra letra, % e max-width pras caixas. clamp fica de bônus.

Tempo

  • 9:30 → 10:30

Mobile-first

Comece pelo celular. Depois, acrescente

desktop-first 
.menu {
  display: flex;
}

@media (max-width: 600px) {
  .menu {
    display: block;
  }
}

começa grande e o celular precisa desfazer

mobile-first 
.menu {
  display: block;
}

@media (min-width: 600px) {
  .menu {
    display: flex;
  }
}

começa simples e só acrescenta

Falar

  • Os dois funcionam. Mas no mobile-first o CSS de cima é o do celular e a tela grande só acrescenta.
  • min-width: 600px = “a partir de 600px pra cima”. max-width: 600px = “de 600px pra baixo”.
  • Por que começar pelo celular? Celular é o mais apertado: se funciona ali, no resto sobra espaço. E o código fica mais curto.
  • Macete: mobile-first usa sempre min-width.

Pergunta

  • “No mobile-first, o que vale entre 0 e 600px?” (só o CSS de cima, sem media query)

Tempo

  • 10:30 → 12:00

Media query

Uma pergunta que o CSS faz pra tela

“A tela tem 500px ou mais de largura?”

Sim

O navegador usa o CSS que está dentro da media query.

Não

O navegador ignora esse pedaço, como se não existisse.

Falar

  • Esquecer o nome difícil. Media query é uma pergunta com SE: “se a tela for assim, usa esse CSS”.
  • Analogia: “Se estiver chovendo, leva guarda-chuva. Se não, ignora.” O navegador faz isso com a largura da tela.
  • Ainda sem código. Só a ideia: sim = usa, não = ignora.

Pergunta

  • “Num celular de 360px, a resposta é sim ou não?” (não)

Tempo

  • 12:00 → 12:45

Como se escreve

A pergunta tem 3 pedaços

@media (min-width: 500px) {
  body { background: blue; }
}

@media “olha como é a tela”

(min-width: 500px) “ela tem 500px de largura ou mais?”

{ } “se sim, usa o que está aqui dentro”

Com ↓ (só você)

  • Cada ↓ acende uma peça do código e a explicação dela: @media → (min-width: 500px) → as chaves.

Falar

  • @media: a palavra que avisa “vou fazer uma pergunta sobre a tela”.
  • min-width: min = mínimo. “A tela tem no mínimo 500px?” 500px ou mais = sim.
  • As chaves: o que fica dentro só vale se a resposta for sim. Dentro cabe CSS normal (body { ... }).
  • Reparar: tem duas chaves de fora (a pergunta) e duas de dentro (body).

Erro comum

  • Esquecer a chave que fecha a media query (a última }).

Tempo

  • 12:45 → 14:00

Com ↓ (só você)

  • Passos: body vermelho (em qualquer tela) → ↓ só a pergunta, vazia (nada muda) → ↓ dentro dela, fundo azul → ↓ uma segunda pergunta (700px), fundo verde.
  • A tela cresce sozinha: vermelho, vira azul em 500px, vira verde em 700px. O número no meio mostra a largura. Arraste a barra “Tela” pra frente e pra trás.

Falar

  • 1: sem media query, vermelho sempre. É o CSS “de base”.
  • 2: a pergunta ainda está vazia. Nada acontece, não tem o que aplicar.
  • 3: agora tem o que aplicar. Menos de 500px = ignora = vermelho. 500px ou mais = azul.
  • 4: cada media query reconhece uma largura diferente. A de 700px vence a de 500px quando as duas são sim, porque vem depois.

Pausa e pratica

  • “Pausem: se eu mudar o 500px pra 300px, em que largura o fundo vira azul?”

Tempo

  • 14:00 → 16:00

Com ↓ (só você)

  • Passos: o básico (2 colunas, serve pro celular) → ↓ a pergunta (min-width: 600px) com 3 colunas dentro.
  • Aqui a tela cresce: começa no celular e vai aumentando. Reparar em quando a grade vira 3 colunas (600px).

Falar

  • O CSS de fora vale pra todas as telas. A media query só entra quando a condição é verdadeira.
  • Lê-se: “se a tela tiver 600px ou mais, aplique isso aqui”.
  • Arrastar a barra “Tela” pra frente e pra trás em cima de 600px: a grade muda na hora.

Ilustrar no navegador

  • No calculadora-cachorro: modo celular do F12, arrastar a largura. Em Elements → Styles a regra da media query acende/apaga.

Erro comum

  • Esquecer o { } de fora ou o de dentro. A media query tem dois níveis de chave.

Tempo

Recap

Um site que se encaixa

  • <meta name="viewport">: a linha mágica do head
  • %, rem, vw: se adaptam. px é fixo
  • width: 100% + max-width: cabe e para de crescer
  • Mobile-first: o CSS base é o do celular
  • @media (min-width: ...): acrescenta nas telas maiores

Mini-desafio

Quando a tela passar de 900px, o fundo da página vira azul-marinho.

Dica: um @media (min-width: 900px) com body dentro.

Falar

  • Passar rápido pelas 5 linhas: cada uma é um slide de hoje.
  • Desafio: não dar a resposta. (@media (min-width: 900px) { body { background: #123f63; } })
  • Bônus: trocar o 3 colunas por repeat(auto-fit, minmax(100px, 1fr)) e ver o que acontece sem media query.
  • Pedir pra testarem no celular de verdade (ou no modo celular do F12) o site que já fizeram.
