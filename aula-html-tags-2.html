Parte 1 · Tabelas

Quando usar uma tabela?

Quando a informação tem linhas e colunas de verdade — aquilo que você faria numa planilha.

  • Ranking de um campeonato
  • Horário das aulas da semana
  • Status dos personagens de um jogo: vida, ataque, defesa

Se dá pra ler “na linha do fulano, na coluna tal, o valor é...”, é tabela.

Parte 1 · Tabelas

Caixas dentro de caixas, de novo

<table>       <!-- a tabela inteira -->
  <tr>        <!-- table row: uma linha -->
    <td>…</td>  <!-- table data: uma célula -->
    <td>…</td>
  </tr>
</table>
tablea caixa de fora
trcada linha, de cima pra baixo
tdcada célula, da esquerda pra direita

Repare: não existe tag de coluna. As colunas aparecem sozinhas quando as células das linhas se alinham.

você escreve

  <tr>
    <td>Ana</td>

  </tr>
  <tr>
    <td>Lucas</td>
    <td>950</td>

Duas linhas, duas células cada → uma grade 2×2. Sem borda, sem cor: deixar bonito é trabalho do CSS.

Parte 1 · Tabelas

Tabela é pra dado, não pra layout

Lá pelos anos 2000, muito site usava tabela pra posicionar coisas na tela: menu numa célula, texto em outra.

Funciona, mas é gambiarra: um leitor de tela vai anunciar “tabela, 3 colunas” pra quem só queria ler uma notícia. Pra arrumar a tela existe o CSS.

Regra rápida: se você apagar as linhas da grade e a informação perder o sentido, era tabela mesmo.

Parte 2 · Formulários

A página que pergunta

Login, cadastro, busca, comentário, chat de jogo: tudo isso é formulário.

Até agora o servidor mandava e você só lia. O formulário é o caminho de volta: você manda algo pro servidor.

<form> → a caixa<input> → o campo<label> → o nome do campo<button> → o envio

Parte 2 · Formulários

<input> — o campo

você escreve 
<form>
  <input type="text"
         placeholder="Seu nick">
</form>
o navegador mostra (pode digitar!)
  • Igual <img> e <br>, o <input> não fecha
  • placeholder = a dica cinza que some quando você começa a digitar
  • Todo campo mora dentro de um <form> — é ele que junta tudo pra enviar

Parte 2 · Formulários

Uma tag, vários tipos

você escreve 
<input type="text">
<input type="email">
<input type="password">
<input type="number">
<input type="checkbox">
<input type="color">
o navegador mostra (teste cada um)

Só trocando o type o navegador muda o campo inteiro: esconde a senha, põe setinhas no número, abre uma paleta de cor. No celular, email até troca o teclado.

Parte 2 · Formulários

<label> — o nome do campo

você escreve 
<label for="nick">Nick:</label>
<input type="text" id="nick">

<input type="checkbox" id="som">
<label for="som">Ativar som</label>
o navegador mostra (clique no texto!)

  • O for do label aponta pro id do campo: os dois ficam ligados
  • Clicar no texto ativa o campo — checkbox fica muito mais fácil de acertar
  • E o leitor de tela sabe ler “Nick” quando chega no campo

Parte 2 · Formulários

<button> — e pra onde vai?

<form action="/inscricao">
  <input type="text" name="nick">
  <button>Enviar</button>
</form>
  • <button> dentro do form = botão de enviar. Apertar Enter num campo faz o mesmo.
  • action = o endereço que recebe os dados · name = o nome do dado lá no servidor
Lembra da aula de como a web funciona? Alguém precisa receber esse pedido. Sem um servidor programado pra isso, o botão envia… pro nada. Por enquanto a gente monta a parte da frente.

Parte 2 · Formulários

Inscrição no campeonato

você escreve 
<form>

    <label for="nick">Nick:</label>
    <input type="text" id="nick">
  </p>
  <p>
    <label for="email">E-mail:</label>
    <input type="email" id="email">
  </p>
  <p>
    <input type="checkbox" id="regras">
    <label for="regras">Li as regras</label>
  </p>
  <button>Inscrever</button>

o navegador mostra

Cada par label + campo vai num <p> só pra ficar um embaixo do outro.

Parte 3 · Semânticas

Tags que dizem o que a parte é

Olhe qualquer site: tem um topo (logo, menu), o meio (o conteúdo) e um rodapé (contato, direitos autorais).

Você entende isso olhando. O navegador, o Google e um leitor de tela não olham — eles leem as tags.

É como etiquetar as caixas de uma mudança: “cozinha”, “quarto”. O que está dentro é o mesmo, mas agora todo mundo sabe onde fica cada coisa.

Parte 3 · Semânticas

<header> e <footer>

você escreve 
<body>
  <header>
    <h1>Arena Pixel</h1>
    <a href="ranking.html">Ranking</a>
  </header>

  <p>Bem-vindo ao torneio!</p>

  <footer>
    <p>Feito pela turma de 2026</p>
  </footer>
</body>
a estrutura
Arena Pixel · Ranking<header>
Bem-vindo ao torneio!
Feito pela turma de 2026<footer>
  • <header> = o cabeçalho da página: nome, logo, menu
  • <footer> = o rodapé: autor, contato, links finais

Parte 3 · Semânticas

Mas na tela não muda nada?

Não. Abra a página: com ou sem <header>, ela aparece igualzinha. E é isso mesmo.

  • Leitor de tela: deixa a pessoa pular direto pro conteúdo, sem ouvir o menu toda vez
  • Google: entende o que é conteúdo principal e o que é só rodapé
  • Você daqui a um mês (e seu colega): acha cada parte do código bem mais rápido

Tem mais da mesma família: <nav> (menu), <main> (conteúdo principal), <section> (uma seção). Mesma ideia: nome certo pra cada parte.

Mão na massa

A página do seu jogo favorito

  • Um <header> com o nome do jogo num <h1>
  • Uma <table> com 3 personagens: nome, vida e ataque (use <th> no topo)
  • Um <form> “Vote no melhor personagem”: um campo de texto, um de e-mail e um checkbox — todos com <label>
  • Um <button> pra enviar
  • Um <footer> com seu nome

Teste: clicar no texto do label marca o checkbox? Então ligou certo.

Desafio: troque o type de um campo pra color ou date e veja o que aparece.
